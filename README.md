# 港股买卖记录

记每一笔港股的**买入 / 卖出**，自动算出成本、持仓市值和盈亏。
成本用**移动加权平均**，和券商 App 里显示的「成本价」一个口径。

**[▶ 在线演示](https://ma-wenqian.github.io/stocks-record/)**（演示数据全是编的，随便改，只存你自己的浏览器）

---

## 这是给谁的

如果你满足以下几条，这个东西大概正合适：

- 手上就**几只港股**，不想为了记账装一套复杂的组合管理软件；
- 想知道的是**「这只股票我到底赚了多少」**，而不是实时行情和技术指标；
- 券商 App 换来换去，或者同时用几家，想有一份**自己的、连续的**记录；
- 现价**手动填**就行 —— 你本来就会去看盘，不需要它替你抓行情；
- 几个人（家人/朋友）各记各的，但**共用一个部署**，互相看不到。

## 特点

- **零依赖**。没有 npm 包，没有构建工具链，没有原生模块。后端只用 Node 内置模块（含 `node:sqlite`），前端是原生 JS。
- **成本口径和券商一致**：移动加权平均，费用计入成本，部分卖出按均价结转。
- **不会让你记出不可能的账**：某一天卖出的股数超过当时持仓会被拒绝 —— 改记录、删记录也会检查。倒着补录历史交易时这个特别有用。
- **代码框可以直接打名称**：输「小米」「中车」「xpeng」自动带出代码并填好名称。
- **多用户各记各的**：部署后每个人一套独立数据，交易和现价都按登录身份隔离。
- **认证交给你已有的 IdP**：应用自己不做登录，前面挂 Authelia / Authentik 之类即可（也可以不挂，只在本机跑）。
- 手机上能用，可以「添加到主屏幕」当 App。浅色 / 深色跟随系统，红涨绿跌。

## 三个口径

| 指标 | 含义 |
| --- | --- |
| **已实现盈亏** | 卖出时结转的部分，钱已经落袋 |
| **浮动盈亏** | 还没卖的持仓：`股数 × 你填的现价 − 持仓成本` |
| **总盈亏** | 已实现 + 浮动 |

```
买入   数量 += q      成本 += q×单价 + 费用      均价 = 成本 ÷ 数量
卖出   结转成本 = 均价 × q
       已实现盈亏 += (q×单价 − 费用) − 结转成本
       数量 -= q      成本 -= 结转成本           均价不变
```

现价没填的股票，暂时按成本价计入市值（浮盈显示 0），看板上会有橙色提示条**点名是哪几只** ——
免得你看着一个「准确」的总市值，其实里面有没更新的。

费用（佣金、印花税、交易征费等）填一个合计数就行：买入时计入成本，卖出时从收入里扣。

> 计算逻辑只有一份 [`public/accounting.js`](public/accounting.js)，**前端、后端、演示页 import 的是同一个文件**，
> 不会出现「网页上算出来一个数、后端算出来另一个数」。

## 快速开始（本机，不需要装任何东西）

需要 Node 22+（`node:sqlite` 从 22 起可用，24 起免实验标志）。

```bash
git clone https://github.com/ma-wenqian/stocks-record.git
cd stocks-record
node server/app.js
```

默认监听 `127.0.0.1:9310`，数据库落在 `./data/stocks.sqlite3`（自动建表，没有「先初始化数据库」这一步）。

⚠️ 应用**自己不做登录**，身份来自请求头 `Remote-User`。本机直接开浏览器会因为没有这个头而停在提示页。
只是想试试的话，先看 **[在线演示](https://ma-wenqian.github.io/stocks-record/)**；
想在本机点着玩，临时在 `server/app.js` 的 `requireUser()` 里写死一个用户即可。

用 curl 试接口：

```bash
curl -H "Remote-User: me" -H "Remote-Name: 我" http://127.0.0.1:9310/api/state
```

## 部署到自己的服务器

想在手机上随时记、或者给家人各开一份，就部署一下。**不用 Docker，不装任何 npm 包**，实测常驻内存 **28MB**。

认证有两种做法：

| 方式 | 适用 |
| --- | --- |
| **forward-auth**（推荐） | 前面已经有 Authelia / Authentik / oauth2-proxy 做认证，应用直接信任注入的 `Remote-User` 头 |
| **不认证** | 只绑 `127.0.0.1`，通过 SSH 隧道或内网访问 |

完整步骤（systemd、反向代理、加人、按用户隔离、备份）见 **[DEPLOY.md](DEPLOY.md)**。

> ⚠️ forward-auth 模式下应用**无条件信任** `Remote-User` 头，所以那个端口**只能绑回环**，
> 防火墙不要放行 —— 否则任何人自带一个头就是你。DEPLOY.md 里有专门一节。

## 怎么用

**记一笔**：右下角 `＋`。选买入/卖出，填代码（或直接打名称）、日期、单价、数量、费用。
总价实时显示；**卖出时还会提前告诉你这笔大概能实现多少盈亏**，按当前均价算。

**看板**：总盈亏、持仓市值/成本、浮动与已实现盈亏、累计投入与费用、持仓分布、已清仓明细。

**持仓**：每只股票的股数、均价、成本、市值、浮盈。**现价直接在卡片上填，停止输入 0.5 秒自动保存。**

**流水**：按日期倒序，点任意一条可以改或删。上方可按代码或名称筛选。

### 常用股票速查表

代码框里打「小米」就能带出 `01810`。表在 [`public/stocks.js`](public/stocks.js)，加一行即可：

```js
{ symbol: '00700', name: '腾讯控股', aliases: ['腾讯', 'tencent'] },
```

⚠️ **加之前务必核对代码** —— 填错的话这只股票的所有记录都会算到别人头上。
表里没有的股票照样能手打代码，不受影响。

代码会自动归一化：`700`、`0700`、`00700.HK`、`hk700` 都存成 `00700`，
不用担心同一只股票被记成好几只。**非数字的代码会被拒绝**，免得凭空造出一只不存在的股票。

## 数据

一个 SQLite 文件，三张表：

| 表 | 内容 |
| --- | --- |
| `users` | 登录过的人（用户名 + 显示名）。**认证不在这里**，只是为了标记归属 |
| `trades` | 每一笔买卖。`created_by` 就是「这笔属于谁」 |
| `quotes` | 手动填的现价，主键 `(user_id, symbol)` |

表结构见 [`server/schema.sql`](server/schema.sql)，全是 `IF NOT EXISTS`，**服务启动时自己跑**。

**每个人的账本是隔离的** —— 交易和现价都按 `user_id` 过滤，卖超校验也只看自己的持仓，
不会借用别人的。详见 DEPLOY.md 的「账本按人隔离」。

金额一律港币，不做汇率换算。

## 开发

```
public/
  accounting.js    记账核心（前端 / 后端 / 演示页共用同一份）
  stocks.js        常用港股速查表（同样三方共用）
  index.html       页面结构
  app.js           前端逻辑（原生 JS，无框架）
  style.css        样式（跟随系统深浅色，红涨绿跌）
  icons/           PWA 图标
server/
  app.js                   后端（零依赖，Node 内置模块）
  schema.sql               表结构，启动时自动执行
  stocks-record.service    systemd 单元
scripts/
  build-demo.mjs   构建 docs/index.html（内联三个模块 + 假后端 + 演示数据）
  make-icons.mjs   生成 PWA 图标（自己拼 PNG，用内置 zlib，零依赖）
docs/
  index.html       构建产物：GitHub Pages 上的演示页
```

```bash
node scripts/build-demo.mjs    # 改完前端重新构建演示页
node scripts/make-icons.mjs    # 改图标样式后重新生成
```

演示页的假后端**复用同一份 `accounting.js` / `stocks.js`**，所以卖超校验、代码归一化、
名称匹配这些行为和真实部署一致 —— 它不是另写一份糊弄人的东西。

构建脚本会检查三个模块拼进同一作用域后**有没有顶层重名**，有就直接报错 ——
静默覆盖比构建失败难查得多。
